Assignment 3: Document Retrieval-Augmented Generation System
Course: Natural Language Processing (Master's in Machine Learning)
Weight: 5% of Final Grade
Prerequisites: Assignments 1 & 2 completed, Docker basics, REST APIs
Deadline: March 11th, 2026

This assignment moves from model training to system engineering. You will design, build, and deploy a complete document intelligence system based on Retrieval-Augmented Generation (RAG). The system runs entirely locally using a quantized LLM served via Docker — no external APIs, no cloud costs.

1. What You Are Building
A user uploads PDF and Word documents to your system. They can then ask any question in natural language and receive a grounded answer citing the relevant source passages. The pipeline has five stages:

Ingest — Parse uploaded documents (PDF, DOCX) and extract clean text
Chunk — Split the text into retrievable units
Index — Store chunks in a search backend (vector or keyword-based)
Retrieve — Find the most relevant chunks for a given query
Generate — Produce a grounded, cited answer using a local quantized LLM
2. Required Components — All Four Are Mandatory
⚠ ALL FOUR COMPONENTS ARE MANDATORY. The entire system must start with a single docker-compose up command:

LLM Service: A quantized language model served locally via llama.cpp (llama-server) or vLLM
MinIO Object Store: Raw uploaded documents (PDF, DOCX) must be stored and managed in MinIO
Flask REST API: Central orchestration layer handling ingestion, retrieval, and generation
Search Backend: A vector or keyword index for chunk retrieval (ChromaDB, Qdrant, Elasticsearch, or SQLite)
You must provide a Dockerfile for the Flask app and a docker-compose.yml that starts everything. No manual setup steps are allowed beyond cloning the repository and running Docker Compose.

3. Document Parsing
Your ingestion pipeline must support at minimum:

PDF files — extract text using pdfplumber or equivalent
DOCX files — extract text using python-docx or equivalent
If a scanned (image-only) PDF is uploaded, your system must detect the empty extraction and return a clear error rather than silently indexing nothing.

4. Chunking Strategy
Implement at least one of the following strategies (more sophisticated strategies are rewarded):

Fixed-Size: Sliding window of N tokens with overlap — simple, fast, good baseline
Recursive Splitting: Split by paragraph, then sentence, then word — preserves author boundaries
Semantic Chunking: Split where cosine similarity between consecutive sentences drops below a threshold
Parent-Child: Index small chunks for precision; return larger parent chunks to the LLM for context
Agentic Propositions: Use the LLM to decompose text into atomic self-contained facts
5. Retrieval Method
Implement at least one of the following methods. You have full freedom of choice:

BM25 / TF-IDF — sparse keyword matching, no GPU required (rank_bm25, Elasticsearch)
Word2Vec / GloVe — average static word vectors with cosine similarity
Bi-Encoder (Dense) — sentence transformer embeddings + ANN search (ChromaDB, Qdrant)
Cross-Encoder Reranker — rerank top-k dense results for higher precision
Hybrid BM25 + Dense — fuse sparse and dense rankings with Reciprocal Rank Fusion (RRF)
HyDE — embed a hypothetical answer generated by the LLM instead of the raw query
Recommended starting point: Fixed-Size Chunking + Bi-Encoder (all-MiniLM-L6-v2) + ChromaDB. This combination runs entirely on CPU and is well-documented. More sophisticated combinations are rewarded in the evaluation.
6. Flask REST API
Your Flask application must expose the following five endpoints:

Method	Endpoint	Description
POST	/documents	Upload a PDF or DOCX file. Returns a document ID.
GET	/documents	List all uploaded documents (ID, filename, upload date).
DELETE	/documents/{id}	Delete a document and its indexed chunks.
POST	/query	Submit a question. Returns the generated answer and the source chunks used.
GET	/health	Health check confirming all services are reachable.
The /query response must include the answer text and the list of source chunks with their document ID, filename, and relevance score.

7. Evaluation and Retrieval Metrics
You must measure and report the retrieval quality of your system using a hand-annotated evaluation dataset:

Build an evaluation dataset: Select 3–5 documents, write 10–20 questions with clear answers, and annotate which passage in the document answers each question. Store it as eval_dataset.json.
Run your retrieval pipeline on each question with k ∈ {1, 3, 5}.
Compute and report: Hit Rate @k, Mean Reciprocal Rank (MRR), and Precision @k.
Qualitative analysis: Show 2–3 success cases and 1–2 failure cases with explanation.
Note: The evaluation dataset and metrics are not compulsory for a passing grade, but they are strongly recommended. Systems with a thorough retrieval evaluation will receive a higher score. Build the habit of measuring what your system actually does.
